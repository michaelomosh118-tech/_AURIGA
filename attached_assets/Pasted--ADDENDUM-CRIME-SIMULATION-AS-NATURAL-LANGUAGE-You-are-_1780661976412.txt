### 4.9 Crime Scenario Generator – Textual Simulation

The system produces **human‑readable crime narratives** that describe, step by step, how a criminal might exploit current weaknesses, along with the Sentinel’s counter‑strategy.

#### 4.9.1 Generation Pipeline

1. **Weakness identification** – The RL “crime chess” engine outputs a set of exploitable gaps (e.g., *“Camera 7 has a 2‑second blind spot when the door opens”*).
2. **LLM narrative synthesis** – A fine‑tuned LLaMA 3 8B model takes these weaknesses plus current environment state (crowd density, time of day, known event types) and generates a **plain‑language crime script**.
3. **Counterfactual simulation** – The system also generates a “what if” version where the crime succeeds, and a “prevented” version where the Sentinel’s auto‑harden actions stop it.

#### 4.9.2 Example Output

**Input to LLM:**  
```
Weakness: Entrance B has no camera coverage for 3 seconds after 6 PM due to lighting transition.
Threat type: pickpocketing.
Recent crime reports: bag snatch near entrance B at 7 PM.
```

**Generated textual simulation:**

> *“At 18:45, a person (ID P004721) loiters near Entrance B. They notice the camera switches to night mode, creating a 3‑second white‑out. During that window, they quickly reach into a nearby shopper’s open bag and extract a wallet. They then merge into the crowd exiting the market. The current rule set does not flag rapid hand movements during camera mode transitions.”*  
> **Suggested mitigation:** Install an IR illuminator to remove the transition blind spot, or add a secondary fixed camera at Entrance B.  
> **Auto‑harden action:** Temporarily increase the bitrate and reduce the exposure transition time from 3s to 0.5s between 6–8 PM.

#### 4.9.3 How It Integrates

- The RL engine’s loophole output → converted to a structured JSON (weakness type, location, time window, required criminal action).
- A lightweight **template‑based generator** creates an initial draft.
- LLaMA 3 (running on the central cluster) rewrites the draft into fluent, actionable prose.
- The final text is stored in the `prevention_schemas` table as a `narrative` field and displayed on the dashboard.

#### 4.9.4 Technical Implementation

We use **guided generation** to keep the LLM on track:
```
System prompt: "You are a security simulation engine. Describe a realistic crime scenario based on the provided weaknesses. Use no more than 150 words. End with one mitigation."
User input: weakness_json + context
```

We quantize LLaMA 3 8B to 4‑bit (using GPTQ) so it runs on a single RTX 4090 in <2 seconds per scenario. The system generates **one narrative per hour** or on‑demand when a new loophole is found.
