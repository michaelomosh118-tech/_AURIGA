## 1. EXECUTIVE SUMMARY

**Drakosanctis Arael** is a fully autonomous, edge‑native video intelligence system designed to detect **criminal potency** in real time, track individuals across non‑overlapping cameras using skeletal biometrics, enhance faces generatively, and **anticipate future threats** by “thinking like a criminal” via a reinforcement learning (RL) chess engine. It requires no third‑party cloud APIs, operates on‑premises, and continuously self‑trains from its deployment environment and optional public intelligence.

**Key differentiators:**
- 33‑keypoint skeleton → 12+ invariant ratios for re‑ID without overlapping cameras.
- Generative face enhancement (GFPGAN) with quality gating.
- Real‑time anomaly detection + predictive potency scoring (LSTM).
- RL‑based “crime chess” that simulates thousands of attack vectors and outputs prevention schemas.
- **Auto‑harden mode** – automatically adjusts camera parameters, PTZ, and virtual audio warnings.
- LLM (LLaMA 3) for reasoning and extracting new threat patterns from text.
- **Textual crime simulation** – generates human‑readable attack narratives and countermeasures.
- 100% independent – no AWS, Google, OpenAI, or proprietary models.

## 4. DETAILED COMPONENT DESIGN

### 4.1 Edge Camera Processing

**Hardware:** Jetson Orin NX (16GB RAM, 100 TOPS)  
**Software stack:** JetPack 6.0, DeepStream SDK, custom Python pipeline.

**Per‑camera pipeline (30 fps):**
```python
while True:
    frame = capture()
    detections = yolo(frame)          # YOLOv8n, 5ms
    keypoints = mediapipe(frame)      # 33 points, 8ms
    tracks = deepsort.update(detections, keypoints)
    
    for track in tracks:
        if track.is_new():
            assign_global_id()
        update_behavior_history()
        if check_anomaly_rules():     # bag, loitering, zone
            send_alert(anomaly)
        if track.is_close():           # bbox height > 120px
            send_face_crop_to_agg()
    
    buffer.write(frame)                # circular, 10 sec
    send_metadata(tracks)             # to aggregation server
```

**Local anomaly rules (edge):**
- Zone violation (polygon defined per camera)
- Object detection: backpack, handbag, firearm (YOLO custom classes)
- Stationary >10 seconds in walking zone

### 4.2 Person Tracking & ID Assignment

- **Tracker:** Deep SORT with cosine metric on appearance features + keypoint consistency.
- **Global ID format:** `P000001` (zero‑padded 6 digits). Persistent across camera reboots.
- **State persistence:** Redis hash `person:{global_id}` stores current camera, last seen timestamp, skeleton signature.

### 4.3 Biometric Signature – 33‑Keypoint Skeleton

**Keypoint set** (MediaPipe Pose 33 + additional finger points):

| Index | Description | Use case |
|-------|-------------|----------|
| 0–10 | Face & torso (nose, eyes, ears, shoulders, hips) | Gaze, orientation |
| 11–22 | Arms & hands (elbow, wrist, each finger joint) | Object handling, weapon grip |
| 23–32 | Legs & feet (hip, knee, ankle, heel, toe) | Gait, running, kicking |

**Invariant ratios computed per person (stored once per appearance):**

1. `shoulder_span / height`
2. `hip_width / shoulder_span`
3. `femur_length (hip→knee) / tibia_length (knee→ankle)`
4. `arm_span (shoulder→wrist) / height`
5. `hand_length (wrist→middle_finger_tip) / height`
6. `index_finger_to_thumb_distance / hand_length` (for grip analysis)
7. `head_height (chin→top_of_head) / height`
8. `ear_to_shoulder_distance / shoulder_span`
9. `knee_angle_at_rest` (for sitting detection)
10. `ankle_to_heel_offset / foot_length` (for limp / unusual gait)
11. `eye_to_eye_distance / head_width`
12. `pelvis_to_shoulder_vertical / height` (torso proportion)

**Cross‑camera re‑ID algorithm:**
- For each new track in camera B, extract its 12‑ratio vector.
- Compare against all active tracks (last 10 seconds) from all cameras using **cosine similarity**.
- If similarity > 0.85 → same ID. If no match → assign new global ID.
- Update central person table with new camera‑specific skeleton (refines the stored vector via running average).

### 4.4 Face Capture & Generative Enhancement

**Trigger condition:** Person bounding box height > 120px **or** detected face bounding box height > 60px.

**Pipeline:**
1. Crop face region using MediaPipe face detector.
2. If face height < 100px → **GFPGAN** (4x upscale, 2 seconds on GPU).  
   Else → **ESRGAN** (denoise + slight sharpen, 0.5 sec).
3. Quality check using MagFace quality score (sharpness, pose, illumination).  
   Threshold: score > 0.6. If below, discard enhanced version, keep original low‑res, and log for manual review.
4. Generate ArcFace embedding (512‑dim vector) for instant watchlist matching.
5. Store:  
   - Original crop (JPEG, 90% quality)  
   - Enhanced crop (PNG)  
   - Embedding (float32[512])  
   - Metadata: camera ID, timestamp, global ID, quality score

**Storage path:** `minio://drakosanctis/faces/{global_id}/{timestamp}_{camera_id}.png`

### 4.5 Behavioral Anomaly Detection

Two parallel subsystems:

#### A. Rule‑based (deterministic, real‑time)
| Rule | Trigger | Output |
|------|---------|--------|
| `took_out_bag` | Person’s hand keypoint enters bounding box of a bag/backpack that was not previously held | Anomaly + timestamp |
| `loitering` | Person’s centroid moves <0.5m over 15 seconds in non‑waiting zone | Anomaly + duration |
| `zone_violation` | Person enters polygon marked "restricted" | Alert |
| `group_exchange` | Two persons <1m apart for >5s and one hand moves toward the other’s pocket | Suspicious exchange |
| `weapon_draw` | Hand keypoint + detected knife/gun object (YOLO) + arm extension | High severity alert |

#### B. LSTM Predictive Model (runs on aggregation server every 2 seconds)
- Input: Last 90 frames of 33 keypoints (normalized) + object presence flags.
- Output: Probability of criminal act in next 5 seconds (0–1).
- Trained on historical incidents (initially synthetic data, then real confirmed events).
- Potency score = max(rule_based_score, lstm_probability * 100).  
  Potency >70 triggers **permanent storage** of rewind clip (last 30 seconds).

### 4.6 Self‑Learning & “Criminal Mind” RL Engine

Runs asynchronously on the central RL cluster.

#### 4.6.1 Reinforcement Learning Environment

We build a **grid‑world simulator** that models a real floor plan (derived from camera layouts).  
State = positions, poses, object holdings of all agents (both normal people and simulated criminals).  
Actions = for criminal agent: `{approach, crouch, distract, pickpocket, drop_bag, run}`  
Rewards = +1 for successful theft, –1 for being detected.  
For Sentinel agent (RL): actions = `{increase_camera_fps, pan_tilt_zoom, send_alert, dispatch_guard, ignore}`  
Reward = +1 for preventing crime, –0.5 for false alert.

We train using **PPO (Proximal Policy Optimization)** in Ray RLlib. After 10 million episodes, the Sentinel learns to anticipate criminal strategies.

#### 4.6.2 “Thinking Like a Criminal” – Adversarial Training

We run a **self‑play loop**:
1. Criminal RL agent tries to find loopholes in current detection rules.
2. Sentinel RL agent adapts.
3. After each iteration, the Sentinel’s new rules are exported to the real‑time system (if they pass a simulation validation).

#### 4.6.3 Loophole Analysis Output

After each training session (daily), the system produces a report:
```
Loophole #124: Criminals can evade face capture by tilting head >45° and wearing a hood.
Mitigation: Add side‑view cameras at choke points or use skeleton gait analysis.
Expected gain: 12% increase in re‑ID accuracy.
```

These reports are logged and can trigger **auto‑harden** if the risk is high (e.g., auto‑request a PTZ camera to change angle).

### 4.7 Prevention Schema & Auto‑Harden Mode

**Prevention schema** – a JSON structure generated daily by the RL engine and LLM:
```json
{
  "valid_from": "2026-06-10T08:00:00Z",
  "valid_to": "2026-06-10T22:00:00Z",
  "context": "Local market day, expected crowd density 0.8",
  "predicted_crimes": [
    {"type": "pickpocketing", "probability": 0.82, "hotspots": ["zone_A", "zone_C"]},
    {"type": "bag_snatching", "probability": 0.45, "hotspots": ["exit_2"]}
  ],
  "auto_harden_actions": [
    {"action": "increase_bitrate", "cameras": [7,8,9], "to": "20Mbps"},
    {"action": "ptz_preset", "camera": 12, "preset": "overhead"},
    {"action": "dispatch_audio_warning", "zone": "exit_2", "message": "Attention, security monitoring active"}
  ],
  "human_required_actions": [
    {"action": "deploy_guard", "location": "zone_A", "reason": "pickpocketing risk >80%"}
  ]
}
```

**Auto‑harden mode** (enabled by user): The system executes `auto_harden_actions` without human approval. Actions are limited to non‑physical interventions (camera settings, audio warnings). Physical guard dispatch requires human confirmation.

### 4.8 Internet Research Module (Opt‑In)

When enabled, the system does the following **without sending any video data**:

1. **Scrape public RSS feeds** from local police blotters, news sites, and security forums (configurable list).
2. **Extract events** using LLaMA 3 70B: “In downtown area, bag thefts increased near bus stops between 6‑8 PM.”
3. **Generate synthetic training data** – e.g., create 3D simulations of people loitering near bus stops, with bag removal motion.
4. **Upcoming events:** Pull local calendars (concerts, strikes, holidays). The RL agent uses this to adjust prevention schema (e.g., higher alert for pickpocketing during a concert).

All scraping is done via a **TOR or VPN proxy** to avoid IP blocking. No personal data is ever sent – only public text.

### 4.9 Crime Scenario Generator – Textual Simulation

This is the **Arael Beam** of the system: converting abstract loopholes into human‑readable attack narratives.

#### 4.9.1 Generation Pipeline

1. **Weakness identification** – The RL “crime chess” engine outputs a set of exploitable gaps (e.g., *“Camera 7 has a 2‑second blind spot when the door opens”*).
2. **LLM narrative synthesis** – A fine‑tuned LLaMA 3 8B model takes these weaknesses plus current environment state (crowd density, time of day, known event types) and generates a **plain‑language crime script**.
3. **Counterfactual simulation** – The system also generates a “what if” version where the crime succeeds, and a “prevented” version where the Sentinel’s auto‑harden actions stop it.

#### 4.9.2 Example Output

**Input to LLM:**  
```
Weakness: Entrance B has no camera coverage for 3 seconds after 6 PM due to lighting transition.
Threat type: pickpocketing.
Recent crime reports: bag snatch near entrance B at 7 PM.
```

**Generated textual simulation:**

> *“At 18:45, a person (ID P004721) loiters near Entrance B. They notice the camera switches to night mode, creating a 3‑second white‑out. During that window, they quickly reach into a nearby shopper’s open bag and extract a wallet. They then merge into the crowd exiting the market. The current rule set does not flag rapid hand movements during camera mode transitions.”*  
> **Suggested mitigation:** Install an IR illuminator to remove the transition blind spot, or add a secondary fixed camera at Entrance B.  
> **Auto‑harden action:** Temporarily increase the bitrate and reduce the exposure transition time from 3s to 0.5s between 6–8 PM.

#### 4.9.3 How It Integrates

- The RL engine’s loophole output → converted to a structured JSON (weakness type, location, time window, required criminal action).
- A lightweight **template‑based generator** creates an initial draft.
- LLaMA 3 (running on the central cluster) rewrites the draft into fluent, actionable prose.
- The final text is stored in the `prevention_schemas` table as a `narrative` field and displayed on the dashboard.

#### 4.9.4 Technical Implementation

We use **guided generation** to keep the LLM on track:
```
System prompt: "You are Arael, the security simulation engine. Describe a realistic crime scenario based on the provided weaknesses. Use no more than 150 words. End with one mitigation."
User input: weakness_json + context
```

We quantize LLaMA 3 8B to 4‑bit (using GPTQ) so it runs on a single RTX 4090 in <2 seconds per scenario. The system generates **one narrative per hour** or on‑demand when a new loophole is found.

## 5. DATA PERSISTENCE & STORAGE

### 5.1 Database Schema (PostgreSQL + PostGIS)

**Table: persons**
```sql
CREATE TABLE persons (
    global_id TEXT PRIMARY KEY,
    skeleton_ratios FLOAT[12],
    height_estimate_cm FLOAT,
    best_face_embedding VECTOR(512),
    first_seen TIMESTAMPTZ,
    last_seen TIMESTAMPTZ,
    total_alert_count INT,
    risk_profile JSONB
);
```

**Table: tracks** (spatial)
```sql
CREATE TABLE tracks (
    id BIGSERIAL,
    global_id TEXT REFERENCES persons(global_id),
    camera_id INT,
    timestamp TIMESTAMPTZ,
    bbox GEOMETRY(POLYGON, 4326),
    keypoints JSONB,  -- 33 (x,y,visibility)
    potency_score FLOAT
);
CREATE INDEX ON tracks (global_id, timestamp);
```

**Table: behavior_events**
```sql
CREATE TABLE behavior_events (
    id BIGSERIAL,
    global_id TEXT,
    event_type TEXT,
    anomaly_score FLOAT,
    timestamp TIMESTAMPTZ,
    video_clip_path TEXT,
    resolution TEXT   -- 'human_confirmed' or 'auto'
);
```

**Table: prevention_schemas** (historical)
```sql
CREATE TABLE prevention_schemas (
    id SERIAL,
    generated_at TIMESTAMPTZ,
    schema JSONB,
    narrative TEXT,   -- human‑readable crime simulation
    auto_harden_executed BOOLEAN,
    effectiveness_score FLOAT
);
```

### 5.2 Object Storage (MinIO)

- **Video clips:** `clips/{global_id}/{timestamp}_{event_id}.mp4` (H.265, 30 seconds, 15 fps)
- **Face images:** `faces/{global_id}/{timestamp}_original.jpg` and `_enhanced.png`
- **Synthetic training data:** `synthetic/{date}/scene_{id}.npz` (keypoints + labels)

Retention policy:
- Non‑alert clips: deleted after 30 days.
- Alert clips: deleted after 1 year unless marked for long‑term storage.
- Face images: kept for 5 years (legal compliance).

## 9. ETHICAL & LEGAL SAFEGUARDS

### 9.1 Compliance
- **GDPR / CCPA:** Automatic blurring of faces for non‑targeted individuals (privacy mode). Data retention maximum 30 days unless explicit incident.
- **Warrant requirement:** Face recognition search against watchlists only after judicial approval.
- **Transparency:** All alerts include a confidence score and reasoning path (which rules fired, which keypoints contributed).

### 9.2 Human Oversight
- **High‑potency alerts (score >90)** require a human security officer to view the clip before any dispatch.
- **Auto‑harden mode** is disabled by default; must be explicitly enabled per camera/zone.
- **Audit log:** Every automated action (including PTZ moves) is logged with timestamp and reason.

### 9.3 Bias Mitigation
- Regular bias audits using diverse test datasets (different ethnicities, ages, clothing).
- Synthetic training data deliberately includes varied skin tones and body types.
- If false positive rate for a demographic exceeds 2× baseline, system halts and requires retraining.
